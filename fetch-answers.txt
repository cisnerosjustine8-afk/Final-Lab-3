1.  What are the main differences between XMLHttpRequest and Fetch API?

XMLHttpRequest (XHR) is an older way to make HTTP requests in
JavaScript. It uses event handlers and callbacks to handle responses.
The Fetch API is newer and uses Promises, making it easier to write and
manage asynchronous requests. Fetch also has a cleaner syntax and works
well with modern JavaScript features. However, XHR has built-in support
for tracking upload progress, while Fetch does not provide the same
simple upload-progress feature.

2.  Why is the Fetch API considered more modern and readable?

The Fetch API is considered more modern because it uses Promises and
works naturally with async/await. Its syntax is shorter and easier to
understand than the event-based code commonly used with XMLHttpRequest.
This makes requests and response handling easier to organize.

3.  What is the purpose of the .then() and .catch() methods in Fetch?

The .then() method runs when a Promise is fulfilled. It is commonly used
to receive the response and process the returned data, such as
converting it to JSON. The .catch() method handles errors that cause the
Promise to be rejected, such as network failures.

4.  What happens when you send a POST request to the placeholder API?

When you send a POST request to a placeholder API such as
JSONPlaceholder, the server receives the data you submit and responds
with a simulated newly created resource. For example, posting a title,
body, and userId to https://jsonplaceholder.typicode.com/posts returns a
response containing those values and a generated id. JSONPlaceholder is
a testing service, so the new resource is not actually saved
permanently.
